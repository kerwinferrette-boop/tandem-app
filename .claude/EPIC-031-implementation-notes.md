### Runtime (programs.js + tandem.html)
- `materializeTemplate(tpl, week)` (programs.js, above getProgram): seed/DB bundle →
  exact getProgram day shape; block lookup by week span; reuses `applyDeload` so
  D4/D14 deload/realization come free; technique only on technique weeks AND
  tech-flagged exercises; authored-only fields `repRange`/`authoredRest`/`technique`.
- `getActiveProgram()` (tandem.html ~L2380): single seam replacing all 8 getProgram
  call sites. `cfg.programSource==='template'` + LS `tandem_adopted_program` →
  materialize; any failure falls back loudly to the generated engine.
- `TECHNIQUE_TIPS` renders rest_pause / drop_set / cardioacceleration as coached
  instructions on the exercise card (copy grounded in seed coaching_notes).
- buildDayHTML/startRest: authored rests via `data-rest` + `authoredRest ??` guards;
  authored reps via `repRange ||` guards; rec repTarget honors `ex.repRange`.
  Generated exercises never carry these fields → generated rendering unchanged.
- Library UI: `#modal-library` + "Browse Program Library" button in modal-goal.
  `openProgramLibrary()` lists published, non-clone templates; `fetchTemplateBundle()`
  joins `exercises(slug)`; `adoptTemplate()` clones template→blocks→days→exercises
  owner-scoped (slug suffixed `-{uid8}`, upsert on slug + child-wipe for re-adopt),
  caches bundle to LS, sets programSource='template', resets to week 1, syncs;
  `revertToGenerated()` flips back (cache kept for painless re-adopt).
- Sync: `program_source` written in syncToCloud upsert, read in syncFromCloud and
  restoreFromCloud cfg builds.
